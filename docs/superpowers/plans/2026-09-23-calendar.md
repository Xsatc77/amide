# Calendar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Calendar tab with month/week/day views of protocol dosing.

**Architecture:** Pure scheduling + layout functions in `app/calendar/` (unit-tested), a thin router `app/routers/calendar.py`, one Jinja template per view, a small JS file for the view dropdown and the details dialog.

**Tech Stack:** FastAPI, SQLAlchemy, Jinja2, vanilla JS, CSS grid, pytest.

**Spec:** `docs/superpowers/specs/2026-09-23-calendar-design.md`

## Global Constraints
- Only the signed-in user's protocols; paused excluded.
- Sunday-start weeks, US week numbers.
- Built in worktree `C:\tmp\amide-cal` (branch `feature/calendar`).

## Review Focus
1. A protocol ended mid-week shows through its `ended_on` day and not after. (`test_window_edges`)
2. Every-N-days / EOD count from the protocol start, not from the calendar's first visible day. (`test_frequencies`)
3. Dec 27–31 of a week that contains Jan 1 is week 1 of the next year. (`test_week_numbers`)
4. More than 4 protocols on one day → "+N more" instead of overflowing the cell. (`test_lanes_overflow`)
5. Another user's protocol never appears on the calendar or in the details JSON. (`test_calendar_privacy`)
